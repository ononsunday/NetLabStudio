# 已实现功能与技术限制

本文件按当前源代码说明可以做什么，以及结果能够支持什么结论。启动、交互、测试和打包的实际验证记录见 [验证结果](VALIDATION.md)。课程覆盖的知识范围大于模拟器实现的协议细节，不能把课程条目当成完整协议栈的实现声明。

## 如何判断结果来源

| 来源 | 可以据此判断的内容 | 使用时的边界 |
|---|---|---|
| 本机观测 | Windows、psutil 和系统命令返回的适配器、地址、路由、连接、接口计数等 | 字段受硬件、驱动、权限和 Windows 隐私设置影响；不可用字段不会用示例数据填充 |
| 指定目标的实际通信 | 本次 DNS、TCP、TLS、HTTP、HTTP/3、WebSocket、SSH、STUN 或本地客户端/服务器的结果 | 只代表本次目标、端口、协议和条件；失败会保留错误与已取得的证据 |
| 导入抓包文件 | 文件中已有的数据包字节、时间戳和协议字段 | 文件可能来自其他设备或由程序合成；解析文件不能证明它是当前电脑的实时流量 |
| 根据观测推导 | 接口计数差计算的速率、捕获字节统计、重复 TCP 序列片段等 | 速率受采样周期影响；重复片段只是可能重传或重复捕获的证据 |
| 教学模拟与本地计算 | 给定配置和随机种子下的模型状态、事件、路径、成本和算法结果 | 不等于 Windows 协议栈、网卡硬件或公网服务的测量结果 |

模拟发送与真实网络服务相互隔离。虚拟数据包可编码为字节交给分析器，但不会送到真实网卡。CPU 指令中的 `SEND` 和 `RECV` 也只作用于教学内存与虚拟消息。

## 网络基础与本机观察

**已实现：** IPv4/IPv6 地址解析、CIDR 和掩码、网络地址、IPv4 广播地址、地址范围与数量、特殊地址属性、逐位二进制 AND、VLSM 规划及地址冲突检查。分片工具计算 IPv4 分片长度和偏移；路径 MTU 工具按路径 MTU 计算后续探测大小。

本机观察读取网卡状态、IPv4/IPv6 与掩码、MAC、MTU、连接速率、网关、DNS、累计收发字节、活动连接、监听端口和进程关联。Windows 路由和防火墙规则按需只读采集。速率监控根据累计字节和实际采样时间计算，页面显示合计曲线与上下行数值。

Wi-Fi 信息来自 `netsh wlan show interfaces`，保留原始本地化字段，并识别 Windows 提供的 SSID、BSSID、频段、信道、信号、无线电类型及连接速率。课程包含 Wi-Fi 4/5/6/6E/7 的差异。

**边界：** IPv6 没有广播地址。VLSM 规划器是 IPv4 地址分配工具。拓扑收到超过接口 MTU 的包时生成丢弃/需要分片提示；它没有把该包分成多个片并在目标重组。IPv6 分片工具不构造源端 Fragment 扩展首部。路径 MTU 模型假设 ICMP 可达，没有模拟 PMTU 黑洞。Wi-Fi 信号百分比不等于精确 dBm；硬件没有报告频段时不会根据 SSID 猜测。

## 局域网与可编辑拓扑

**已实现：** 电脑、笔记本、服务器、交换机、路由器、接入点和互联网教学节点；设备拖动、端口连接、缩放和平移；接口、地址、MAC、网关、静态路由、VLAN、DHCP、NAT 与链路参数编辑；拓扑 JSON 导入/导出、本地保存和示例载入。

转发核心根据共享设备、接口和链路状态计算 ARP/邻居查询、缓存、源 MAC 学习、目的 MAC 查表、同 VLAN 内泛洪、Access/Trunk 与允许 VLAN、IPv4/IPv6 转发、最长前缀匹配、TTL/Hop Limit、ICMP 回显、链路带宽队列、传播延迟和丢失。VLAN 间转发可以通过虚拟路由器配置实现。数据包保留当前位置、状态、封装及相关事件。

DHCPv4 服务有地址池、OFFER、ACK/NAK、租约到期和续约时间；申请会检查客户端与服务端是否处于可达的广播域，并配置客户端地址和网关。生成树根据当前拓扑计算转发树，阻塞冗余链路，拓扑变化后更新树与 MAC 学习表。Wi-Fi 关联/漫游使用距离、SSID 和认证配置选择接入点。

页面可以单步、播放、暂停、重置，关闭设备或链路后保留已排入的事件。快照保存等待队列、随机状态、包、邻居表、学习表、租约、NAT 与链路队列；恢复后可以继续运行。虚拟帧可以交给抓包分析页查看。

**边界：** DHCP 是有状态的服务交换模型，DORA 步骤不是完整 UDP 广播报文经过每条链路的模型；没有 DHCP 中继或 DHCPv6。ND 用链路内泛洪近似 solicited-node 多播，没有完整 NUD、DAD、Router Advertisement 或 SLAAC 状态机。生成树使用最小树教学计算，没有 BPDU、桥 ID 选举、端口状态定时或完整 STP/RSTP。以太网没有 CSMA/CD 电气碰撞模型。Wi-Fi 没有射频、OFDMA、MIMO、WPA 密码学或 802.11 帧空口模拟。

## IP、路由与互联网

**已实现：** 静态路由与最长前缀匹配，Dijkstra/Bellman-Ford 逐步计算，RIP 距离向量轮次、OSPF 全图最短路径、BGP 邻居路径传播、AS_PATH 与重复 AS 拒绝。拓扑页可以将教学算法结果安装到虚拟路由表；链路改变后重新计算撤回与替代路径。路由环路可通过错误配置与 TTL 耗尽观察。

NAT44/PAT 保存协议、内部地址/端口、外部地址/端口和过期时间，支持反向映射及显式端口转发。示例包含 IPv6、多个路由器、VLAN、Trunk 与家庭网络。真实功能读取 Windows 路由表，并调用有界的 Ping/Traceroute。

**边界：** RIP 没有完整报文、定时器、split horizon 或 poison reverse；OSPF 没有邻接状态机、LSA 洪泛和多区域；BGP 没有 eBGP/iBGP 会话、路由反射、LOCAL_PREF/MED 或商业策略。算法结果按模型安装，不代表真实协议的完整收敛时延。路由页的图算法节点不要求是配置了 IP 的真实虚拟路由器，拓扑页的路由安装才检查接口与二层可达性。NAT 只实现 NAT44，不实现 NAT64/NAT66。CGNAT 属于课程与穿透教学配置。没有 IP 地理数据库或物理位置推断。

## TCP、UDP 与 QUIC

**TCP 已实现：** 客户端/服务器握手和关闭状态、序列号与累计 ACK、滑动发送窗口、接收窗口限制、超时/控制包重试、快速重传、Reno 风格慢启动、拥塞避免和快速恢复、RTT/Karn 采样、RTO 与指数退避。延迟、抖动、丢失、带宽、接收窗口和种子影响实际计算出的事件。另有已建立连接的 Keepalive 与 RST 控制实验。

**UDP 已实现：** 数据报划分、传输延迟、乱序与丢失统计；核心 API 可以开启应用层 ACK、超时重试与去重。载荷校验演示和完整虚拟 UDP 帧分析是不同层级的工具。

**QUIC 已实现：** 有丢失/重试的握手教学状态、TLS 集成阶段标记、包号与流偏移、独立流交付、PTO 恢复以及连接迁移的路径验证标记。传输页可以按相同条件比较三种模型。真实 HTTP/3 使用独立的 aioquic 服务，不调用这个教学模型。

**边界：** TCP 模型没有 SACK、延迟 ACK、完整选项协商和生产协议的全部状态；TIME_WAIT 不按真实 MSL 等待。Keepalive/RST 是单独的控制实验，RST 有效性输入不是完整 RFC 5961 接收窗口检查。拓扑中的 TCP 只模拟连接建立，可靠数据传输和关闭实验在传输页进行。UDP 教学校验值是载荷校验，不是完整伪首部与首部校验。QUIC 模型没有线格式编码、真实加密、拥塞控制、0-RTT 或 HTTP/3 QPACK；迁移验证包没有独立丢包模型。模型策略不同，吞吐量不能作为生产 TCP、UDP、QUIC 的速度排名。

## DNS、HTTP、HTTPS 与现代 Web

**已实现：** 指定域名的 A、AAAA、CNAME、MX、TXT、NS 查询与记录解析；成熟库执行普通 DNS、DoH 和 DoT；虚拟 DNS 记录、TTL 和缓存；GET/HEAD/POST/OPTIONS、请求 Header、正文、状态、响应 Header、耗时与有限正文预览；HTTP/1.1、协商 HTTP/2、实际 HTTP/3 GET；TLS 协议、证书、主机名/路径验证与可取得的证书链信息。WebSocket 有实际收发服务。

内置回环测试服务支持 HTTP/HTTPS、HTTP/2、HTTP/3、DNS、DoH、DoT；生成的临时本地证书只通过显式 CA 文件用于测试，不写入系统信任库。Web 页直接提供 HTTP/HTTPS 启动按钮；其余服务可以通过编程页已列出的类型或服务 API/自动化测试使用，API 支持不等于每个服务都有独立 GUI 启动菜单。

“访问网站”有两个入口：真实探测逐项执行 DNS、TCP、TLS 和 HTTP；教学实验计算解析、连接、TLS、请求及响应阶段。

**边界：** 真实 DNS 查询通过递归解析器完成，没有声称观察根/TLD/权威服务器的全部实际迭代。DNSSEC 是课程内容，未实现完整验证器。虚拟 DNS 中根/TLD/权威步骤是解释性标记。网站真实探测的阶段使用独立连接，不是浏览器同一会话抓包。教学网站实验的 TLS/HTTP 是按传输状态插入的阶段，不编码双向 HTTP 请求响应或执行证书密码学。HTTP/3 工具当前为 GET，没有浏览器页面渲染、资源依赖加载或完整站点性能分析。Cookie、Session、缓存、CDN、反向代理和负载均衡有课程与可检查的 Header，没有完整浏览器 Cookie/缓存存储或可编排代理/CDN 集群。不能解密未知密钥的 HTTPS。

## 安全与 VPN

**已实现：** 真实 TLS 握手与证书验证，SSH 密钥交换与主机公钥指纹检查；本机可信回环 SSH 使用固定的主机公钥执行 `netlab-info`；真实 SHA-256、密钥交换、认证加密、数字签名及篡改检测；Windows 防火墙只读查看、虚拟规则匹配；TLS 1.3/会话恢复教学时序；VPN 分流、封装、加密与不加密的本地比较。

**边界：** 外部 SSH 指纹读取没有完成可信身份核对，不登录或执行第三方命令。密码学实验调用 cryptography，不自行开发密码算法；临时密钥不是生产密钥管理。虚拟防火墙不是 Windows Filtering Platform，没有完整连接跟踪。VPN 演示不会建立网卡、修改真实路由或提供商业 VPN；没有实现 WireGuard 的真实握手、密钥轮换和传输协议，WireGuard 原理来自课程。TLS 链展示受 Python/SSL API 影响，能成功验证握手不代表所有链证书字段都能被界面列出。

## 游戏网络与 P2P

**已实现：** 一维小游戏同步，客户端预测、带序号输入、服务端权威状态、插值及显示误差；延迟和丢失参数改变位置与事件。NAT 教学配置决定直接候选或中继路径，结果说明实际 NAT 的映射/过滤差异。服务 API 可对明确 STUN 目标执行 Binding 查询，回环 STUN 服务用于真实报文测试。诊断页提供指定目标的稳定性图表。

**边界：** 没有完整 ICE、认证 TURN 中继或跨公网真实打洞部署。一次 STUN 映射查询不能判定 NAT 类型或保证穿透；CGNAT 也不必然禁止打洞。小游戏没有碰撞、回滚、输入重放或具体商业游戏协议。Minecraft、虚拟局域网和游戏部署有课程内容，没有内置 Minecraft 服务端或第三方服务器访问能力。稳定性工具中的 TCP 连接耗时/失败率不是 UDP 丢包率或某个游戏的 Ping；ICMP RTT/丢包通过 Ping 单独取得。

## 抓包与协议分析

**已实现：** PCAP/PCAPNG 导入，按时间与协议展示，源/目标地址和端口，Ethernet、ARP、IPv4/IPv6、TCP、UDP、ICMP、DNS 等字段与原始 Hex，TCP 会话片段时序和流量统计。虚拟拓扑包有教学来源标记。实时抓包限定明确接口、持续时间和数量，并先检测 Npcap 能力。无驱动时离线文件和教学分析仍可用。

**边界：** 文件默认最多解析 10000 包，API 可调整到 100000 包，单文件限 256 MiB；这不是大型生产流量分析器。当前电脑未安装 Npcap，实时驱动抓包没有实机验证。重复 TCP 片段可能为重传或重复捕获；不能断言捕获了完整会话。没有完整 TCP 字节流重组、应用文件还原、TLS 密钥日志解密或流量取证系统。文件来源与采集环境由提供者说明，不能仅因可解析就认为是本机实测。

## 日常诊断与网络编程

**诊断已实现：** 适配器/地址/网关检查、DNS、Ping、Traceroute、单个 TCP 端口、TLS/HTTPS、TCP 连接稳定性、错误证据与诊断建议；历史保存与导出。综合探测有总时限与取消处理。Windows 系统命令以参数数组或固定脚本调用，不把用户主机名拼成 Shell 命令。

**编程已实现：** Python 和 C 编辑器、输出、超时与错误；回环 TCP/UDP、聊天室、文件传输、HTTP、WebSocket、select、asyncio、多线程、缓冲区和异常示例。内置服务只绑定回环地址，支持 TCP/UDP/HTTP/HTTPS/HTTP2/HTTP3/WebSocket/SSH、聊天室和文件收发。文件实验验证回传字节，聊天室可向多个已连接客户端广播。C TCP/UDP 使用 Windows Winsock 与 GCC/Clang。

**边界：** 诊断是证据向导，没有未经允许修改 IP、DNS、防火墙或路由器；没有网段扫描或自动发现第三方设备。网关不回应 ICMP 不能独自证明故障。编辑器执行的是本机子进程，有时间和输出限制，Windows 用 Job Object 清理后代，仍不是文件系统/网络安全沙箱。便携版内置 Python 练习运行时支持随包示例和已打包的库；其他第三方包需使用源码环境，C 需编译器。应用自身启动不依赖外部 Python 或 C 编译器。示例默认回环，用户自行修改代码后仍需自行确认目标授权。文件服务是有限大小的教学传输，不是生产文件服务器。

## 课程、记录与报告

**已实现：** 178 个中文知识点，分为网络基础、局域网、路由、传输、Web、安全、游戏、抓包、诊断、编程、组成原理和操作系统。每项包含概念、过程、例子、字段/工具、针对性题目、答案解释、现有相关条目链接与参考资料。支持按关键词/类别搜索、学习进度、题目作答、错题、笔记，以及自由、引导和挑战模式。挑战模式可隐藏直接讲解，综合故障挑战可提交判断。

SQLite 保存设置、进度、笔记、答案、实验、拓扑与模板，按版本迁移。支持实验 JSON、CSV、备份导入/导出和 Markdown 报告；导入事务校验与重复 ID 保留。快照与原始拓扑用于恢复可运行实验，分享副本可脱敏；支持删除记录与清除个人数据。

**边界：** 每个条目至少一道选择题，不是适应性题库、考试评分系统或完整教材。引导模式提供步骤和关联工作区，没有逐项强制验证所有课程目标。报告保留配置与结果证据，实验目标使用通用文字，个人总结需要填写。备份/CSV/报告默认脱敏，普通实验 JSON 和拓扑快照保留原始配置。脱敏只识别常见结构化字段与地址，不能保证识别任意正文、代码和 Hex 载荷。脱敏备份中的地址不适合直接恢复网络拓扑。没有账户、云同步或远程数据上传功能。

| 页面置换 | FIFO、LRU、OPT，逐次页面状态、命中、缺页率 | OPT 使用未来访问作为理论比较；没有磁盘交换、页表多级遍历或真实分页文件管理 |
| 网络 I/O | 系统调用、用户/内核缓冲、复制、DMA、发送/接收、排队、背压/溢出、interrupt/polling 与 CPU 成本 | 固定教学成本并允许参数比较；没有 TSO/RSS、零拷贝、真实驱动或多核网卡队列 |

独立 CPU `SEND` 将消息放入明确标注的教学回环接收队列；`RECV` 从该队列读出。跨模块 E 使用外部虚拟接收队列：先真实运行虚拟拓扑转发，只有请求到达目标后才生成虚拟 UDP 回显，回包到达来源后才更新接收内存/队列。网络失败会保留丢弃或阻塞，不能靠独立回环制造成功。

## 桌面交互、性能与验证边界

原生 PySide6 窗口提供 19 个工作区、中文、深浅主题、可收起导航/知识面板、全局课程搜索、可排序/筛选表格、结构/JSON 证据、画布与时序播放。真实网络和代码子进程使用 Worker，最多同时接纳三个后台任务；关闭时停止计时器、等待有界任务、停止服务并关闭数据库。模拟核心不依赖 GUI，可由自动化测试直接验证。

窗口最小尺寸为 1000×680；复杂输入主要使用 JSON 编辑器，尚无完整向导式端口/路由/电路属性面板。大量数据仍保留 JSON，结构树只展开前 1000 项。模型与解析器设置输入、事件、包、时间及输出上限，未进行百万包或大型拓扑性能认证。

目前没有完成的外部环境验证包括：安装 Npcap 后的实时抓包、管理员专属抓包模式、所有 Wi-Fi 6E/7 驱动字段、跨家庭公网 NAT/IPv6/HTTP3/SSH 环境，以及其他电脑上的完整便携部署。当前测试不是全 Windows 10/11 硬件兼容性认证，也没有代码签名、安装向导或自动更新器。具体测试数量和打包结果以 [验证记录](VALIDATION.md) 为准，不在本文件中把尚未运行的检查写成通过。
